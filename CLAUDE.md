# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Local [Strudel](https://strudel.cc) live-coding harness. Node stdlib only (plus `acorn` for the resolver, `@breezystack/lamejs` for mp3, and `playwright-core` as a dev dependency for headless renders), no build step, no bundler. Songs are `songs/*.strudel`; everything (code and samples) is served from this folder.

## Commands

    npm install
    npm run samples                    # one-time ~300 MB pack download (resumable, re-run on failures); `-- <pack>` for one pack
    npm start                          # http://localhost:3000 (PORT env overrides)
    npm run stop [-- <port>]           # kills whatever is listening on that port (default PORT, else 3000)
    npm run pages                      # static copy in dist/ for GitHub Pages (deployed by .github/workflows/pages.yml on push to main)
    npm test                           # node:test suite in test/
    node --test test/check.test.mjs    # one test file
    npm run check -- songs/x.strudel   # headless: dumps 4 cycles of events (+ axis table, key, chords for song() files), fails on syntax errors / unknown sounds
    npm run check                      # every song, summary only
    npm run dump -- songs/x.strudel    # read-only: print the plain Strudel a song()/section() file reduces to
    npm run note -- songs/x.strudel --ask "..." --change "drop.melody.brightness .5>.7 why..."   # record why a change was made (songs/x.notes.json); --prompt "..." sets the song's summary
    node gen/euclid.mjs --seed=3 > songs/euclid.strudel
    npm run form -- --mood=ominous --bars=64 --seed=5 > songs/new.strudel   # a song skeleton: roles, bars, harmony and axis values shaped by the mood (lib/overlays.json); then material first
    npm run lint -- songs/x.strudel    # musical lint over the check table: no climax, climax not the peak, identical sections, raw saws together, seeded melody/bass, axes out of 0..1; exit 1 on errors
    npm run headless -- songs/x.strudel   # opens the page in a headless Chromium (playwright-core, or CHROME=<binary>) so render/verify run with no window; starts the server if none answers

Axis workflow (page must be open for anything that renders; a render stops playback first):

    npm run resolve -- <song> <section|*> <layer|*> "phrase" [--write]   # words -> axis deltas -> edit numeric literals
    npm run render -- <song> [--section s] [--layer l] [--cycles n] [--mp3]
    npm run mp3 -- renders/x.wav [--kbps 192]
    node scripts/analyze.mjs renders/a.wav [renders/b.wav] [--json]
    npm run verify -- <song> <section> <layer> "phrase"                  # render -> resolve --write -> check -> render -> analyze -> report
    npm run vocab                                                        # regenerates .claude/skills/strudel/reference/vocab.md from code

Tests write temp files prefixed `_t_` into `test/`, `songs/`, and `samples/user/` and delete them after, so `npm test` runs serially (`--test-concurrency=1`): in parallel, one file's `_t_` fixtures show up in another's scan of those shared directories. `test/_scope.mjs` builds the Node strudel scope once and loads `lib/` into it; import its `ready` promise in tests that need patterns.

**Any change under `lib/`, `scripts/`, `web/`, `gen/` or `server.mjs` ends with `npm test`, and a failure is fixed in the same turn** — not reported back as a question. Read the failing assertion first and decide which side is wrong: a test pinning behaviour that deliberately changed gets updated (say so in the report), a test catching a real break gets the code fixed. `test/golden.test.mjs` is the exception: never regenerate it to make it pass; a moved fixture means lib changed how songs build, so confirm only the expected fixtures moved before `UPDATE_GOLDEN=1`.

## Claude's feedback loop

Claude can't hear audio. `npm run check` is the primary verification: it prints the event stream (time, duration, value) and flags any `s("...")` name not in the local packs, `samples/user/`, or the hardcoded synth list `SYNTHS` in `lib/packs.mjs` (the page's sound datalist reads the same list). For measurable axes (brightness, weight, width, density, space, articulation) `npm run verify` renders before/after and reports metric deltas; "verified directionally" is the strongest claim to make. For browser verification use the Playwright MCP: navigate to `http://localhost:3000/#song.strudel`, click play, and read the console for `[strudel] evaluated` or error text in `#err`. Navigating to a URL that differs only by hash does not reload the page.

The `strudel` skill (`.claude/skills/strudel/`, the one folder under `.claude/` that is versioned: `SKILL.md` and the generated `reference/vocab.md`) is the song-editing workflow: baseline → resolve → check → render/verify → report → commit with the musical change as the message. The check table now carries form and words: each section's `energy` (onsets per cycle summed over its parts, scaled by level) printed as an `arc:` line, and each layer's axis values read back as vocabulary words (`describeAxes` in `lib/vocab.mjs`, the reverse of `parsePhrase`), so "what does it sound like" and "does the climax peak" are answered from the table. `test/golden.test.mjs` pins `test/fixtures/*.strudel` (copies of songs, kept still: a change there is a change in lib), while the songs in `songs/` only have to check clean (`test/check.test.mjs`).

## Architecture

- **server.mjs** exports `createServer()` and `userMap()`. Routes: `/` (index.html), `/songs/index.json` (list), `GET|PUT /songs/<name>` (name must match `^[\w.-]+\.(strudel|notes\.json)$`: a song and its provenance file `<song>.notes.json`, which `scripts/note.mjs` writes and `web/compose.mjs` `notesView` merges with the source comments for the Compose card), `/events` (SSE, fires `{changed}` from `fs.watch` on `songs/` and `{render}` jobs), `/samples/user/strudel.json` (generated sample map), `/assets/` (aliases `@strudel/web/dist/assets` so the clock SharedWorker resolves), and static passthrough for `/node_modules/`, `/samples/` and `/lib/` only.
- **Render routes** (the page renders; Node drives it): `POST /render` pushes the job over SSE and waits up to 60 s, `PUT /renders/<name>.wav[?mp3]` receives the result (converted with `wavToMp3` when asked), `POST /render-error` rejects the waiter. The page's export buttons do not need the server: MP3 renders and encodes in the browser (`web/mp3.mjs` wraps lamejs for both the page and `scripts/mp3.mjs`), Strudel downloads the expanded pane; with a server they also `PUT /renders/<name>.mp3|.txt` so the file lands in `renders/`.
- **Two pages, one look**: `index.html` (Compose) and `examples.html` (Examples) share `web/boot.mjs` (`boot()` = initStrudel + prebake + lib load, `playCode`, `expandCode` = in-browser `lib/dump.mjs`, `nav`, `footer`) and `web/strudel.css`; `about.html` and `legal.html` are static prose pages that import only `nav`/`footer`. Every page carries a description, canonical URL and og tags (`web/og.png`) pointing at `https://jonborchardt.github.io/strudel-bench/`; the server serves any root `[\w-]+.html` that exists, and `scripts/pages.mjs` copies the `PAGES` list plus `404.html` and `web/` and writes `sitemap.xml` and `robots.txt` from `PAGES` only. `404.html` is what GitHub Pages serves for any unknown path at any depth, so it injects a `<base>` at the site root (first path segment on github.io, the origin elsewhere) before its relative links; the server returns it for unknown paths a browser navigates to (`Accept: text/html`) and plain text otherwise. `web/compose.mjs` holds the Compose page's DOM-free helpers (`kitsIn` = the kits of `lib/kits.json` whose bd/sd/hh are among the loaded sound names, `notesView`, the request-card text), tested in `test/compose.test.mjs`. Compose is laid out as song header → transport → source/expanded panes → feedback/notes cards; the kit selector is a native popover menu (`#kit` button + `#kits`) with a filter box matching name or label, each entry showing the kit's `icon` (`web/kits/<kit>.svg`: a drum-hit glyph whose texture, weight, colour and accent are picked by words in the description by `node scripts/kiticons.mjs`; legend in `docs/superpowers/kits.md`) left of the kit name over its one-line `label` from `lib/kits.json` (`about` is the hover title; `docs/superpowers/kits.md` is the long form); the notes card shows `songs/<name>.notes.json` merged with source comments. Examples renders `GROUPS` from `web/examples.mjs` (title, blurb, tags, variants of `hll` or `src`, optional `svg` at 219×135 and `explain`) through one `card()` function: variant buttons load and play (A/B), the HLL pane is an editable textarea that re-expands 300 ms after each edit and re-evaluates while that card is playing, Play plays the pane as edited; adding an example is a data edit (`test/examples.test.mjs` checks every variant evaluates), `stub: true` renders a dashed placeholder. `test/pages.test.mjs` rejects root-absolute URLs in the pages, including a `'//'` string literal.
- **index.html** loads `@strudel/web` straight from node_modules (UMD global `strudel`). `prebake` (now in `web/boot.mjs`) reads `samples/packs/packs.json`, registers each `<pack>.json` plus the user map, and applies the tidal-drum-machines alias bank so `.bank("RolandTR909")` works. SSE reload re-evaluates if playing; unsaved textarea edits get a reload link instead. `fs.watch` fires twice on Windows, hence the 200 ms debounce. Transport: one play/pause toggle plus stop; pause (and scrubbing while paused or stopped) remembers the cycle because the worker clock resets on stop, Play evaluates and starts from it, an edit while playing shows an Update button (ctrl+enter) that re-evaluates in place, and the section list comes from a scheduler-free evaluation (`evalCode`) so the slider works before the first play. `renderOffline` renders offline one cycle at a time (a single `renderPatternAudio` graph runs ~40x slower than realtime on long songs) on an OfflineAudioContext while the live context stays open (the scheduler's clock is bound to it for the life of the page) and is restored afterwards; a `WeakRef` patch keeps superdough's node pool from handing one context's nodes to the other, and the cross-context error a straddling onended cleanup throws is filtered from the console. Exports lock the export group and report on the `#xstate` badge (rendering n%, ✓ file, ✗ why).
- **Sample maps** are Strudel JSON (`{_base, sound: [files]}`). `scripts/samples.mjs` downloads packs from the Strudel CDN, rewrites `_base` to `/samples/packs/<name>/`, and appends the name to `packs.json`. Pack contents are gitignored; the `.json` maps are committed so `npm run check` knows the sound names on a fresh clone. When `samples/packs/packs.json` is absent (GitHub Pages), index.html streams the packs listed in `lib/packs.json` from the Strudel CDN with the same base URLs `scripts/samples.mjs` downloads from. All page URLs are relative because a project page lives under `/<repo>/`; `scripts/pages.mjs` assembles `dist/` (including lamejs for the browser mp3 encoder) and the page saves to localStorage and hides the request card when `/events` 404s.
- **Local packs** (`samples/user/<pack>/`): `userPacks()` in server.mjs scans one folder per pack (inside: subfolder = sound with variants, loose audio file = single-variant sound; `pack.json` = `{ deploy: true | false | [sounds], license, source }`, absent = local-only) and `userMap(packs)` merges them into one Strudel map. Routes: `/samples/user/strudel.json` (merged map) and `/samples/user/packs.json` (the index the page reads into `localPacks` for the header badge and status line). A song declares its packs with `packs: [...]` in the song() header (a `META_KEYS` entry) or in a comment for plain files; `lib/packs.mjs` `packsOf(src)` reads both and `packKind` names deployed / local / missing. `checkCode(code, file, cycles, packs)` keeps the unknown-sound rule and adds two problems: a local-pack sound the song does not declare, and a declared pack that is not present. `scripts/pages.mjs` ships only `deploy` packs (whole or subset), requires `license` to deploy, drops songs declaring a non-shipping pack from `songs/` and `index.json`, and re-runs `checkFile` against the shipped index for songs declaring packs so the build fails rather than playing silence online. `samples/user/demo-pack` + `songs/ping.strudel` are the deployed example.
- **scripts/check.mjs** runs Strudel in Node: `evalScope` over core/mini/tonal with stubbed `setcps`/`samples`/`hush`, loads `lib/index.mjs`, `evaluate(code, transpiler)`, then `pattern.queryArc(0, 4)`. Bank-prefixed sounds resolve as `<bank>_<name>`. Exports `checkFile` and `ensureScope` for the other scripts. For `song()` files each section carries `energy` (onsets per cycle over its parts, scaled by level) and each layer `words` (`describeAxes`); the CLI prints the words after each layer's attrs and an `arc:` line of section energies with bar glyphs.
- **lib/dump.mjs** has no source to print (song() builds patterns at runtime), so `dump(code, { modules, Pattern, evaluate })` wraps every core function and Pattern method for the duration of one evaluation, records the call chain behind each pattern, prints it per section and layer, and then restores the originals. Every dump opens with `prebakeHeader` (`lib/packs.mjs`, built from `lib/packs.json`): the `samples()`/`aliasBank()` calls the page runs at boot, plus the deployed `samples/user/` map when the song declares packs, because strudel.cc prebakes a different set and a paste would otherwise warn "sound not loaded". `scripts/dump.mjs` drives it from Node (`dumpFile`), `index.html` from the page: the expanded pane re-expands the textarea 300 ms after each edit (and on play), so it reflects the textarea, not disk, and the Strudel export/open buttons use that same expansion. On GitHub Pages, save and new song fall back to localStorage under a `strudel:` prefix and the song list merges those drafts.
- **lib/resolve.mjs** parses the song with acorn and edits only numeric literals that are direct values of axis keys inside `section()` layer objects, plus the `key`/`progression` strings for harmony words. Signals and hand-written expressions are refused, never rewritten. `scripts/resolve.mjs` is its CLI; the Compose page imports it too (an import map in `index.html` points `acorn` at `node_modules/acorn/dist/acorn.mjs`, which `scripts/pages.mjs` ships) for the **Mix card**. The card shows one section (the playhead's, or the pinned one) as a layers × axes grid of sliders: `setAxis` rewrites or inserts one literal in the textarea; a layer built with spread shows the evaluated song's values and a drag appends an override after the spread; only a signal shows `expr`. Words go in as pills in the open **adjust via vocabulary** panel under materials (Verify's comparison lands inside it; the status line stays outside, since knobs and previews write it too): the box is a native `<datalist>` of the vocabulary tables plus the section's part names (`listTerms`, rebuilt by `mixRender`), and only a term becomes a pill (Enter/Tab/comma on the typed word or on a prefix only one term starts with; a pick from the list arrives as a `change` event), a part pill scopes the pills after it to that part, and each clause runs `planEdits` (which takes the evaluated attrs as a fifth argument so spread layers resolve; the CLI without them still refuses spread layers). Verify renders the section before and after the words with `renderSong`, measures both with `lib/analyze.mjs` (the analyzer's pure half; `scripts/analyze.mjs` keeps the wav I/O and CLI), shows the deltas per requested axis (`verifyRows` in `web/compose.mjs`) next to a player for each with a close button, reports progress on an `xstate` badge, and applies the edit. The **arrangement strip** sits under the card's header: a block per section, flex-grown by span, one row per layer shaded by density × level, click to scrub, the playing one outlined, with a pin (loop it, Play starts there, the card stays on it, a plain click on another block moves the pin: the scheduler is handed the section's own pattern at its own cps via `scheduler.setPattern`, which loops by itself with nothing scheduled past its edges, and the page converts between song cycles and section bars with `toSong`/`toLocal`; unpinning hands the song pattern back at the equivalent cycle), rename (the ✎ op or a double-click on the name opens a box in the block; `renameSection` rewrites the name literal and refuses empty, quoted or taken names), move-earlier/later arrows (`moveSection` swaps the two call texts), duplicate (`duplicateSection`, next free numbered name) and remove (`removeSection` cuts the call with its line and separator). Two closed panes, **song** (above the strip, since it is not about one section) and **section** (above the knobs), are `spanPane`s: a CodeMirror 6 editor (`web/cm-editor.mjs` `createEditor`, loaded straight from node_modules through the import map in `index.html`, which `scripts/pages.mjs` ships package by package) over one span of the source. `show(node)` re-reads the span after every edit (`setText`), and an edit in the pane (typing, a control, an alt-drag) splices the source at that span through `commit`, so the knobs, expansion and player follow; while a pane or one of its controls has focus (`typing()`) `mixRender` re-finds its span by start position (a section's name may be mid-edit) and leaves the text alone, and undo blurs it first. The song pane shows the header object of `song(...)` (`locate` returns it as `song`) parsed as one expression (`languageFor('song')`, lezer's `SingleExpression` top) with `root: 'song'`, so its keys read as song's; the section pane shows the whole `section(...)` call. The editor has no history extension: ctrl+z reaches the page's stack. `web/cm-controls.mjs` is the inline-control extension, an experiment ahead of moving the main pane to CodeMirror: `web/hll-schema.mjs` says which literals have known semantics (`props` by object key inside a `song`/`section` object, its layer objects, or a `map` such as `drums.sounds`: numbers with bounds, enums, bools; `calls` by positional argument: section's cycles; `free` names the keys that stay hand-written, and a test checks every key the HLL accepts is in one or the other; `host.sounds`/`host.kits` are getters the page fills with what is loaded) and everything else stays plain code; `findControls` re-finds them from the lezer tree after each change (a state field, half-typed code included), each gets a dotted underline, the **controls** checkbox in the panel's summary (`#tweak`, kept in localStorage) puts a widget after each (`editFor` dispatches the replacement of exactly that literal, quantized to the spec), and alt-drag on a known number changes it in place (the codemirror-interact gesture, bounded by the spec; open numbers step every 8 px). Strudel expressions in a value are covered too: `signals` (`sine`, `saw`, ...) as a pick, `methods` (`.range`, `.slow`, `.fast`, `.segment`) and `calls` (`ramp`) by argument, where `'inherit'` means the bounds of the HLL number the expression is the value of. The widgets are in `web/cm-widgets.mjs`, one factory per kind chosen by `widgetFor`: slider (number with a max), spinner (number with only a min), check, tokens (the progression as a row of chord pick buttons plus +, brackets kept), pick (a `button.pick` like the materials panel's that opens the host's menu, with a ▶ when the value can be heard) and select (the native fallback without a host). The host hooks come in through `createEditor({ ui })`: the page's `editorUi(sectionAt)` gives `pick` (the shared `#pick` popover through `openPickList`, which the materials panel's `openPick` now also uses; its preview level slider hides when the menu has no play buttons), `audition`/`canAudition` (the materials audition path by control path in the section `sectionAt(control)` names, `auditionKit` for `kit`) and `icon` (the kit svg). The **Song source** pane is the same editor: `code = createEditor({ light: true, ... })` replaced the textarea, `code.text`/`code.setText` are what `$('code').value` was everywhere, its `onChange` is what typing was (commit, `sourceChanged`, `expandSoon`), a control's section is the call around it (`sectionAround`), and its header carries a third controls checkbox (`#tweak2`, after `#tweak0` on the song pane and `#tweak` on the section pane; `setTweak` keeps all three editors and the `strudel:tweak` setting together). Its controls take the page's light styles under `.pane`, the rack's dark ones under `.rack`. Tested in `test/cm.test.mjs` on `EditorState` alone, the chooser included. An **add part…** dropdown ends both the axes and the materials list (`#addaxes`, `#addmats`, one option per kind, filled by `mixRender`): a pick inserts `layer: {}` (`addLayer`) and the re-render puts the dropdown back on its placeholder; the × on a knob row removes one (`removeLayer`); a second part of a kind is `drums2`, which `song()` builds with the layer named by the key minus its trailing digits (`layerBase`). A closed **materials** details under the knobs shows one line per part: drum `template` (select over `TEMPLATES`) and per-voice `sounds`, the `sound` of the other parts, bass and melody `notes` (the written line; empty = the seeded line), melody `phrase` (shown as bars; 1 is dropped) and `follow`, pad `arp`. Template, arp, sound and the drum voices are `button.pick` menu buttons that open the one shared `#pick` popover (filter box, rows from `TEMPLATES`, `ARP_ORDERS` or the `#snds` datalist of synth names plus every loaded sample); every row carries a ▶ that **auditions** without selecting, and the text boxes (notes, bars) show a ▶ while focused. Each row ends with a **level** slider (0..2, the part's gain multiplier; 1 is dropped from the source), the volume control the axes lack. The kit menu rows carry the same ▶ (a `span.pv`, since a button cannot nest one): `auditionKit` plays the same two bars (`KIT_GRIDS`: twelve voices, the house groove with rim and cowbell, then ride, crash, clap and a tom fill) through that kit at the shown section's tempo, so every kit is heard on the same material; voices the kit lacks (`hasSound`) are dropped and named in the status. All of these go through `preview(btn, build)` / `run` (build returns `{ pattern, cps, what }`); `audition()` is the material case. It pauses the song (so Play says Resume), resumes the AudioContext itself (it may be the page's first click, and superdough's `initAudio` does not actually resume), evaluates the source with `setMaterial` applied, and hands the scheduler only that section's layer pattern for two bars at the section's cps through the repl's `setCps`/`setPattern` (the `setcps` global only exists once a song has been evaluated); pressing the same ▶ again, or closing the menu, ends it early. A drum voice previews alone through `voiceSound` from `lib/layers.mjs` (the drums part's own rule: a name the kit has keeps the kit, `rim` → `RolandTR909_rim`; any other sample plays bare, because superdough looks up `<kit>_<name>` and nothing else once `.bank()` is set; `hasSound` in `lib/strudel.mjs` asks the page's sound map and is undefined in Node, which then assumes the kit), because the built part would drown it or, below the voice's density threshold, not contain it at all. A **preview level** slider sits at the bottom of the panel and again in the menu header (`input.pvin`, log scale x0.1..x50, `pvGain` kept in localStorage under `strudel:pvlvl`, never written to the song): every preview is multiplied by it, and a running one restarts on release. Values come from the source literal or the evaluated song (a spread); `matText` builds the literal (`sounds` is the whole voice map with one voice replaced) and a change goes through `setMaterial` (`locate` records material properties as `mats`, literal or `expr`; null text removes the key). Every source change (typing, knobs, pills, section ops, kit) goes through one undo stack in the page (`commit`), coalescing typing and knob drags within a second; ctrl+z / ctrl+shift+z and undo/redo buttons on both the source pane and the mix header (`.undo`/`.redo`). The expanded pane scrolls its changed line into view by setting its own scrollTop, never scrollIntoView, so a mixer click does not move the page. **What you hear vs what is written**: solo/mute (M and S on a knob row, sets of part names) and A/B (the summary button: the source before the last undo step, evaluated with `evalCode`, on the same clock; any commit turns it off) never touch the source. `audible(pat)` derives the scheduler's pattern from an evaluated song: the pinned section's parts alone, or the song rebuilt with `stepcat` the way `song()` arranges it, keeping only the parts that pass; `setLive()` hands it to the scheduler, and `play`/`applyPin` go through it. `globalThis.strudelBench.live()` returns the scheduler's current pattern for headless checks. The "all sections" checkbox on the phrase row makes words and knobs land in every section that has the part (`planEdits` with `'*'`, `setAxisScoped`). Keys: space plays/pauses outside text fields, ctrl+s saves, ctrl+enter updates; `beforeunload` asks when there are unsaved edits. Export renders the pinned section alone as `<song>.<section>.mp3`. **Seeing**: under each knob row an event strip (`evRow`) draws the part's onsets over the section's bars from the evaluated song, with bar lines from `--bars` and a playhead from `--ph` on `.knobs`, which `showPosition` sets while the shown section sounds. **Harmony row** above the knobs (`harmRender`): the section's key (the song's, marked, unless the section names one) and one pick per bar of the progression showing the chord name over its numeral, plus a + bar; picks go through `setSectionField` (key/progression on the section: replace, insert after role, or drop) with the `CHORDS`/`ROOTS` lists exported by `web/hll-schema.mjs`; the transport readout appends the chord under the bar (`chordAt`). **Seed per part**: `song()` gives every layer `seed` as material (`lctx`), the melody row in materials has a seed box (placeholder: the song's) and a next button. **Provenance**: `did` remembers every mixer edit in `pending` (a drag coalesces), and Save appends them to `songs/<name>.notes.json` as one dated request, "edits made in the mixer", with layer/axis/to parsed from knob messages so the notes card tags them (`saveNotes`; local server only). **Share link**: the export group's Link button copies `<page>#s=<base64url(deflate-raw("name\nsource"))>` (`shareEncode`/`shareDecode` in `web/compose.mjs`, native CompressionStream, tested in Node); `loadList` decodes `#s=`, lists the name if it is a legal song name, and puts the source in the editor unsaved, then sets the hash to the name so a reload does not re-import. **Transitions**: each strip block (except the last) ends with two picks, `riser` (bars of sweep at the end of this section, `fx.riser`) and `hit` (the next section's `fx.impact`, with a preview); `withFx` adds an fx part when the section has none, and the values shown come from the evaluated sections.
- **gen/** generators are plain scripts that print Strudel code to stdout with a seeded PRNG; each exports `generate(seed)` so tests can run output through `checkFile`. `gen/form.mjs` (`generate(seed, { mood, bars })`, `MOODS`) emits a `song()` skeleton: the `ARC` of six roles with base values per part, bars in fours from the length, `FEEL` per mood (mode, verse and climax progression words from `lib/harmony.json`, tempo), and the mood's `lib/overlays.json` vector added to every part where it pushes hard or where the part already sets that axis; `test/gen.test.mjs` generates every mood and checks it clean with a climax.
- **scripts/lint.mjs** exports `lint(checkResult)` → `[{ level, section?, text }]` over the check's sections (energy, layers with attrs): the skill's rules as findings (no climax, climax not the peak, identical consecutive sections, raw saws sharing a section by effective sound with `lib/layers.mjs` defaults, melody/bass without notes, axes outside 0..1 as errors, level outside 0..2). CLI over songs/, exit 1 on errors; `test/lint.test.mjs` feeds it hand-built results.
- **scripts/headless.mjs** launches Chromium through `playwright-core` (dev dependency; `CHROME` env for another binary), starts the server when nothing answers on the port, opens the page on a song and waits for the packs line, then stays up so `render`/`verify` jobs run in it. Web Audio, the clock SharedWorker and the offline renderer all work headless.

## Node gotcha

`@kabelsalat/web` (pulled in by `@strudel/core`) ships no `exports` map, so Node resolves its CJS build and named imports break. Any Node script importing `@strudel/*` must `import './esm-fix.mjs'` (a `registerHooks` resolve hook) first and then use dynamic `import()` for the strudel packages, as `scripts/check.mjs` does. `lib/` never imports `@strudel/*`: it reaches Strudel through `lib/strudel.mjs` (`S`), which is `window.strudel` in the page and `globalThis` after `evalScope` in Node.

## Axes

A song can be written declaratively: `song({ cps, key, seed, kit }, [section(name, cycles, { role, key, progression, drums: {...}, bass: {...}, melody: {...}, pad: {...}, fx: {...} })])`. Each layer takes axis values in 0..1, where **0.5 is the baseline no-op** (enforced by test) and a continuous axis may also take a Strudel signal or `ramp(a, b)`; structural axes take numbers only. `key` and `progression` are per-section harmony (rule 4: harmony is material, not an axis); material keys (`sound`, `level`, `fill`, `arp`, `follow`, `kit`, `meter`, `bpm`, ...) live next to axes in the same layer/section objects. `test/golden.test.mjs` pins the full event stream of the fixture songs in `test/fixtures/`; regenerate it (`UPDATE_GOLDEN=1 node --test test/golden.test.mjs`) only on purpose, when lib changed how songs build, and check that only the fixtures you expected moved.

- `lib/axes.mjs` — the 12-axis registry (`AXES`), `PHASES` (structural → timing → pitch → articulation → spectral → spatial → level), and the `ctl`/`piece` mapping helpers.
- `lib/layers.mjs` — the five layers (drums, bass, melody, pad, fx) and their per-axis cells.
- `lib/grid.mjs` (step grids and placement, parametric on meter), `lib/song.mjs` (`song`/`section`/`registerLayer`), `lib/harmony.mjs` (roman-numeral progressions over a section key, `chordName`, harmony words), `lib/vocab.mjs` (phrase → axis deltas; `MODIFIERS` scale them).
- `lib/index.mjs` loads all of it into the current scope and defines `song`, `section`, `strudelLib` and one global per layer (`drums({ density: .8 })` returns just that layer's pattern) on `globalThis`.
- Vocabulary is data, not code: `lib/descriptors.json` (control words), `lib/overlays.json` (emotions/genres), `lib/harmony.json` (progression and mode words). Node reads them eagerly, the page fetches them via `/lib/`. Add words there, then `npm run vocab`.

README.md carries the rules, the axis table, the phase order and the harmony contract, because `docs/` and `.claude/` (except the strudel skill) are gitignored here.

## Deliberate deferrals

The expanded Strudel pane is still a `pre`; `@strudel/codemirror`'s pattern highlighting is not wired in (both editors are `web/cm-editor.mjs`, the JavaScript language only). GM soundfont instruments (`gm_*`) still stream from GitHub. Harmony does not model inversions, voice leading, or chords longer than a bar. Design spec and plan: `docs/superpowers/`.
