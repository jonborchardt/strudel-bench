# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Local [Strudel](https://strudel.cc) live-coding harness. Node stdlib only (plus `acorn` for the resolver, `@breezystack/lamejs` for mp3, and `playwright-core` as a dev dependency for headless renders), no build step, no bundler. Songs are `songs/*.strudel`; everything (code and samples) is served from this folder.

Song flags are comment lines: `// @hidden` keeps a song off the song dropdown (`listedSongs` in server.mjs filters `songs/index.json`, local and Pages) while it still loads by `#name.strudel`, checks and ships; `// @blog` means the blog links to that song, so never delete or rename it (nothing in this repo reads it, the blog adds it).

## Commands

    npm install
    npm run samples                    # one-time ~300 MB pack download (resumable, re-run on failures); `-- <pack>` for one pack
    node scripts/samplemeta.mjs        # after a download: seconds/rms/peak of every wav into samples/packs/<pack>.meta.json (committed, the check reads them)
    npm start                          # http://localhost:3000 (PORT env overrides)
    npm run stop [-- <port>]           # kills whatever is listening on that port (default PORT, else 3000)
    npm run pages                      # static copy in dist/ for GitHub Pages (deployed by .github/workflows/pages.yml on push to main)
    npm test                           # node:test suite in test/
    node --test test/check.test.mjs    # one test file
    npm run check -- songs/x.strudel   # headless: dumps 4 cycles of events (+ axis table, key, chords for song() files), fails on syntax errors / unknown sounds
    npm run check                      # every song, summary only
    npm run dump -- songs/x.strudel    # read-only: print the plain Strudel a song()/section() file reduces to
    npm run note -- songs/x.strudel --ask "..." --change "drop.melody.brightness .5>.7 why..."   # record why a change was made (songs/x.notes.json); --prompt "..." sets the song's summary
    node gen/euclid.mjs --seed=3 > songs/euclid.strudel
    npm run form -- --mood=ominous --bars=64 --seed=5 > songs/new.strudel   # a song skeleton: roles, bars, harmony and axis values shaped by the mood (lib/overlays.json); then material first
    npm run lint -- songs/x.strudel    # musical lint over the check table: no climax, climax not the peak, identical sections, raw saws together, seeded melody/bass, axes out of 0..1; exit 1 on errors
    npm run measure -- songs/x.strudel <section> [--cycles n] [--json]   # page open: renders the section's mix and every part alone (four bars unless --cycles), prints dB under the mix, depth (with relativeDb/highRatio/tail next to it), pan, and the masking pairs; writes renders/<song>.<section>.measure.json
    npm run lint -- --measure renders/x.s.measure.json      # mix lint over that: no headroom, inaudible/dominant part, flat stage, masking low/mid, no depth contrast
    npm run headless -- songs/x.strudel   # opens the page in a headless Chromium (playwright-core, or CHROME=<binary>) so render/verify run with no window; starts the server if none answers

Axis workflow (page must be open for anything that renders; a render stops playback first):

    npm run resolve -- <song> <section|*> <layer|*> "phrase" [--write]   # words -> axis deltas -> edit numeric literals
    npm run render -- <song> [--section s] [--layer l] [--cycles n] [--mp3]
    npm run mp3 -- renders/x.wav [--kbps 192]
    node scripts/analyze.mjs renders/a.wav [renders/b.wav] [--json]
    npm run verify -- <song> <section> <layer> "phrase"                  # render -> resolve --write -> check -> render -> analyze -> report
    npm run vocab                                                        # regenerates .claude/skills/strudel/reference/vocab.md from code

Tests write temp files prefixed `_t_` into `test/`, `songs/`, and `samples/user/` and delete them after, so `npm test` runs serially (`--test-concurrency=1`): in parallel, one file's `_t_` fixtures show up in another's scan of those shared directories. `test/_scope.mjs` builds the Node strudel scope once and loads `lib/` into it; import its `ready` promise in tests that need patterns.

**Any change under `lib/`, `scripts/`, `web/`, `gen/` or `server.mjs` ends with `npm test`, and a failure is fixed in the same turn** — not reported back as a question. Read the failing assertion first and decide which side is wrong: a test pinning behaviour that deliberately changed gets updated (say so in the report), a test catching a real break gets the code fixed. `test/golden.test.mjs` is the exception: never regenerate it to make it pass; a moved fixture means lib changed how songs build, so confirm only the expected fixtures moved before `UPDATE_GOLDEN=1`.

## Claude's feedback loop

Claude can't hear audio. `npm run check` is the primary verification: it prints the event stream (time, duration, value) and flags any `s("...")` name not in the local packs, `samples/user/`, or the hardcoded synth list `SYNTHS` in `lib/packs.mjs` (the page's sound datalist reads the same list). For measurable axes (brightness, weight, width, density, space, articulation) `npm run verify` renders before/after and reports metric deltas; "verified directionally" is the strongest claim to make. For browser verification use the Playwright MCP: navigate to `http://localhost:3000/#song.strudel`, click play, and read the console for `[strudel] evaluated` or error text in `#err`. Navigating to a URL that differs only by hash does not reload the page.

The `strudel` skill (`.claude/skills/strudel/`, the one folder under `.claude/` that is versioned: `SKILL.md` and the generated `reference/vocab.md`) is the song-editing workflow: baseline → resolve → check → render/verify → report → commit with the musical change as the message. The check table now carries form, load and words: each section's `energy` (onsets per cycle summed over its parts, scaled by level) and its `form` letter (`formLetters`: the same set of sounding parts shares a letter, a prime marks energy far off that letter's first section, so ABAB reads off the line) printed as an `arc:` line, its `voices` (hits sounding at once, length plus release summed over the whole pattern in the section's window, a `stack()` of textures around the song included and printed as `n outside the parts`; a hit with a worklet effect, `coarse`/`crush`/`shape`/`distort`, counts one more per effect, since each is a JavaScript processor run every quantum; each plain hit is ~8 audio nodes, and past ~40 the audio thread cannot render in real time on a laptop, which the lint says) on its header line, and each layer's axis values read back as vocabulary words (`describeAxes` in `lib/vocab.mjs`, the reverse of `parsePhrase`), so "what does it sound like" and "does the climax peak" are answered from the table. `test/golden.test.mjs` pins `test/fixtures/*.strudel` (copies of songs, kept still: a change there is a change in lib), while the songs in `songs/` only have to check clean (`test/check.test.mjs`).

## Architecture

- **server.mjs** exports `createServer()` and `userMap()`. Routes: `/` (index.html), `/songs/index.json` (list), `GET|PUT /songs/<name>` (name must match `^[\w.-]+\.(strudel|notes\.json)$`: a song and its provenance file `<song>.notes.json`, which `scripts/note.mjs` writes and `web/compose.mjs` `notesView` merges with the source comments for the Compose card), `/events` (SSE, fires `{changed}` from `fs.watch` on `songs/` and `{render}` jobs), `/samples/user/strudel.json` (generated sample map), `/assets/` (aliases `@strudel/web/dist/assets` so the clock SharedWorker resolves), and static passthrough for `/node_modules/`, `/samples/` and `/lib/` only.
- **Render routes** (the page renders; Node drives it): `POST /render` pushes the job over SSE and waits up to 60 s, `PUT /renders/<name>.wav[?mp3]` receives the result (converted with `wavToMp3` when asked), `POST /render-error` rejects the waiter. The page's export buttons do not need the server: MP3 renders and encodes in the browser (`web/mp3.mjs` wraps lamejs for both the page and `scripts/mp3.mjs`), Strudel downloads the expanded pane; with a server they also `PUT /renders/<name>.mp3|.txt` so the file lands in `renders/`.
- **Three pages, one look**: `index.html` (Compose) and `examples.html` (Examples) share `web/boot.mjs` (`boot()` = initStrudel + prebake + lib load, `playCode`, `expandCode` = in-browser `lib/dump.mjs`, `nav`, `footer`) and `web/strudel.css`; `about.html` and `legal.html` are static prose pages that import only `nav`/`footer`. Every page carries a description, canonical URL and og tags (`web/og.png`) pointing at `https://jonborchardt.github.io/strudel-bench/`; the server serves any root `[\w-]+.html` that exists, and `scripts/pages.mjs` copies the `PAGES` list plus `404.html` and `web/` and writes `sitemap.xml` and `robots.txt` from `PAGES` only. `404.html` is what GitHub Pages serves for any unknown path at any depth, so it injects a `<base>` at the site root (first path segment on github.io, the origin elsewhere) before its relative links; the server returns it for unknown paths a browser navigates to (`Accept: text/html`) and plain text otherwise. `web/compose.mjs` holds the Compose page's DOM-free helpers (`kitsIn` = the kits of `lib/kits.json` whose bd/sd/hh are among the loaded sound names, `notesView`, the request-card text), tested in `test/compose.test.mjs`. Compose is laid out as song header → transport → source/expanded panes → feedback/notes cards; the kit is set through the song pane's `kit` control (the shared `#pick` menu, filter box, a ▶ per kit), each entry showing the kit's `icon` (`web/kits/<kit>.svg`: a drum-hit glyph whose texture, weight, colour and accent are picked by words in the description by `node scripts/kiticons.mjs`; legend in `docs/superpowers/kits.md`) left of the kit name over its one-line `label` from `lib/kits.json` (`about` is the hover title; `docs/superpowers/kits.md` is the long form); the notes card shows `songs/<name>.notes.json` merged with source comments. Examples renders `GROUPS` from `web/examples.mjs` (title, blurb, tags, variants of `hll` or `src`, optional `svg` at 219×135 and `explain`) through one `card()` function: variant buttons load and play (A/B), the HLL pane is an editable textarea that re-expands 300 ms after each edit and re-evaluates while that card is playing, Play plays the pane as edited; adding an example is a data edit (`test/examples.test.mjs` checks every variant evaluates), `stub: true` renders a dashed placeholder. `test/pages.test.mjs` rejects root-absolute URLs in the pages, including a `'//'` string literal. The third page, **`samples.html`**, is local-only: the server returns it like any root `[\w-]+.html` file, but it is not in `scripts/pages.mjs`'s `PAGES` list (so it never ships) and carries `noindex`; `web/boot.mjs`'s `nav()` links it with a `hidden` attribute that Compose clears once its `/events` SSE connection opens, i.e. once a local server is behind the page. Its job is to make and audition sample definitions, never to edit a song: a left column lists the user packs with their sounds and definitions, a new-pack form and a drop target that imports a file into the selected pack (the existing `SAMPLE_FILE` PUT route); the main column edits one definition through the same `web/waveform.mjs`/`web/sampler.mjs` pair Compose uses, plus name, sound, bars/slices, a test pattern and bpm for auditioning. It boots Strudel the same way Compose does, so auditions play through the same scheduler. Save/Duplicate/Delete write the definition into the pack's `pack.json` (`packJsonWith` builds the replacement object, `defText` the definition literal itself, `nameProblem` checks the name is free) via the same PUT route, with a confirm before a destructive one; `web/workshop.mjs` holds these DOM-free helpers, tested in `test/workshop.test.mjs`.
- **index.html** loads `@strudel/web` straight from node_modules (UMD global `strudel`). `prebake` (now in `web/boot.mjs`) reads `samples/packs/packs.json`, registers each `<pack>.json` plus the user map, and applies the tidal-drum-machines alias bank so `.bank("RolandTR909")` works. SSE reload re-evaluates if playing; unsaved textarea edits get a reload link instead. `fs.watch` fires twice on Windows, hence the 200 ms debounce. A hap that fails to sound (a `raw` part naming a sound that is not loaded) is caught by the repl's trigger so the rest keeps playing, but logged without the error type; `boot()` matches the `[getTrigger] error` line too, so `#err` says which sound instead of the part just being silent. Transport: one play/pause toggle plus stop, and a **scope** canvas (`#scope`: `setLive` hands the scheduler the pattern with `.analyze(1)`, so superdough's analyser 1 is the mix; `scopeDraw` runs a frame loop while playing and prints the peak in dBFS, held a second, red at clipping); pause (and scrubbing while paused or stopped) remembers the cycle because the worker clock resets on stop, Play evaluates and starts from it, an edit while playing shows an Update button (ctrl+enter) that re-evaluates in place, and the section list comes from a scheduler-free evaluation (`evalCode`) so the slider works before the first play. `renderOffline` renders offline one cycle at a time (a single `renderPatternAudio` graph runs ~40x slower than realtime on long songs) on an OfflineAudioContext while the live context stays open (the scheduler's clock is bound to it for the life of the page) and is restored afterwards; a `WeakRef` patch keeps superdough's node pool from handing one context's nodes to the other, and the cross-context error a straddling onended cleanup throws is filtered from the console. Exports lock the export group and report on the `#xstate` badge (rendering n%, ✓ file, ✗ why).
- **The stage** (`web/visual/`) is the song's visual performance, a card under the transport. `lib/visual.mjs` `composeVisual` gives the score at every play (two bars of onsets per section on the page, `onsetsOf(ir, 2)`); `web/visual/host.mjs` is the DOM-free core (`eventOf`: a tapped hap as an event with its part, what `classifyHap` reads, gain/velocity/pan/cutoff/room, its audio-clock `t` and pattern `cycle`; `clockOf`: the musical moment of a song cycle, section, bar, beat phases, energy, riser and dropout tails, boundary; `createPerformance`: a world run at a fixed 1/60 step between the page's clock readings, events delivered on the step their audio time passes, `reset` from the score's seed on a discontinuity, `flush` on a pause); the worlds are `web/visual/tunnel.mjs` (a wall of rings at the tempo: continuous motion, depth, a section role as the scene) and `web/visual/ink.mjs` (the song paints one sheet, time left to right in section bands, marks wet then dry, the last frame the painting; it paints only what is new, since the canvas persists between draws, the host's contract), both `{ name, init(score, rng, size), step(state, dt, events, clock), draw(state, ctx, w, h) }` (randomness only from the state's own seeded generator in `kit.mjs`, so the same score and stream give the same state, and the tests forbid `Math.random` and the clocks; units are the canvas height, never pixels; `?vdebug=<kind>` solos one kind's events for tuning); `web/visual/stage.mjs` is the DOM side (`mountStage`: canvas sizing, the frame loop, the per-part `tap`, the `?vdebug` overlay, fullscreen). In `index.html` `audible()` wraps each playing part in `.onTrigger(stage.tap(part, kind), false)` (dominant false: superdough still sounds it), or the whole pattern once for a plain file or a wrapper around a song (machine's textures), so nothing fires twice; the stage's clock is `scheduler.now() - latency × cps` (the scheduler works its lookahead ahead of the ear) in song cycles through `toSong`, events fire at their `targetTime` against the audio context's `currentTime`. Play from stopped resets the world, a resume or an Update keeps it (same seed, world and palette), stop clears, seek and pin reset. A score naming a world that is not built runs on tunnel and the overlay says so. Tested in `test/visual-host.test.mjs`, `test/visual-tunnel.test.mjs` and `test/visual-ink.test.mjs`; the look is judged live, with the music.
- **Sample maps** are Strudel JSON (`{_base, sound: [files]}`). `scripts/samples.mjs` downloads packs from the Strudel CDN, rewrites `_base` to `/samples/packs/<name>/`, and appends the name to `packs.json`. Pack contents are gitignored; the `.json` maps are committed so `npm run check` knows the sound names on a fresh clone. When `samples/packs/packs.json` is absent (GitHub Pages), index.html streams the packs listed in `lib/packs.json` from the Strudel CDN with the same base URLs `scripts/samples.mjs` downloads from. All page URLs are relative because a project page lives under `/<repo>/`; `scripts/pages.mjs` assembles `dist/` (including lamejs for the browser mp3 encoder) and the page saves to localStorage and hides the request card when `/events` 404s.
- **Local packs** (`samples/user/<pack>/`): `userPacks()` in server.mjs scans one folder per pack (inside: subfolder = sound with variants, loose audio file = single-variant sound; `pack.json` = `{ deploy: true | false | [sounds], license, source, samples }`, absent = local-only) and returns `{ <pack>: { sounds, samples, problems, deploy, license, source } }`: `samples` is the pack's own name → definition map read from `pack.json`'s `samples`, validated against `DEF_KEYS` and the pack's own sounds (a bad entry lands in `problems`, never thrown, so one typo does not break the index). `userMap(packs)` merges just the `sounds` of each pack into one Strudel map. Routes: `/samples/user/strudel.json` (the merged sound map) and `/samples/user/packs.json` (the whole index above, including `samples` and `problems`, the page reads into `localPacks` for the header badge, status line and sound pick). A song declares its packs with `packs: [...]` in the song() header (a `META_KEYS` entry) or in a comment for plain files; `lib/packs.mjs` `packsOf(src)` reads both and `packKind` names deployed / local / missing. `checkCode(code, file, cycles, packs)` keeps the unknown-sound rule and adds two problems: a local-pack sound the song does not declare, and a declared pack that is not present. `scripts/pages.mjs` ships only `deploy` packs (whole or subset), requires `license` to deploy, drops songs declaring a non-shipping pack from `songs/` and `index.json`, and re-runs `checkFile` against the shipped index for songs declaring packs so the build fails rather than playing silence online. `samples/user/demo-pack` + `songs/ping.strudel` are the deployed example.
- **Sample parts** (`sample: { sound, begin, end, bars, slices, pattern, stretch, transpose }` in `lib/layers.mjs`): a trimmed region of any loaded sample (fractions of the file) standing for `bars` bars at the section tempo, cut into `slices` equal pieces (or, when `slices` is a list, at those break points, fractions of the file inside the region) (`slicePoints` folds the trim into the n+1 point array `slice()` takes, because `.slice()` overwrites an earlier `.begin()/.end()`), sequenced by `pattern` (mini-notation of slice indices spanning the sample's bars, every index validated against the count; unwritten, `samplePlan` defaults it to every slice in order, so `sample: { sound: 'loop' }` plays the loop as recorded). `sound` may also be a list of definitions sharing `bars` and slice count, each keeping its own region (keyed by take index, so `['loop-kick', 'loop-snare']`, which both resolve to the pack sound `loop`, are two distinct takes: a kick or a snare per hit, picked deterministically). A pack may also define named samples in its own `pack.json` (`samples: { name: { sound?, begin?, end?, bars?, slices?, stretch? } }`, the keys `DEF_KEYS` in `lib/packs.mjs`): `registerSamples(packIndex)` fills the module-level `SAMPLES` registry from every pack's `samples` in name order, so a collision with another pack's definition or sound has one winner everywhere and the loser is named in `SAMPLE_PROBLEMS`; `resolveSample(attrs)` puts a named definition's keys under a sample part's own (which win) and resolves `sound` to the pack sound (keeping a `:n` variant), and `samplePlan` calls it before validating. Each host that builds sample parts registers its own pack index first: `scripts/check.mjs` and `scripts/dump.mjs` against `userPacks()`, `scripts/pages.mjs` against the shipped subset (dropping a definition whose sound falls outside a `deploy` list), the page against `/samples/user/packs.json`. `transpose` (semitones) multiplies that speed by `2**(transpose/12)`, so pitch and length move together with no pitch-preserving stretch. Natural playback is `.speed(cps*(end-begin)/bars).unit('c')` (superdough: `playbackRate = speed × file duration`), `stretch` computes the per-step speed (`cps/step × slice width`, what Strudel's `.fit()` does) from the section `cps` that `song()` puts in `sctx`, not from the scheduler's `_cps` that `.fit()` reads — so a section with its own `bpm` is right and `npm run check` (which queries with no controls) and the page agree; `lib/dump.mjs` prints the closure with the number inlined via a `toString`, as `piece`/`ramp` do in `lib/axes.mjs`. The Compose page's materials row for a sample part (`waveRender`, `auditionSlice`, `importSample` in `index.html`) decodes the file behind the sound through `web/preview.mjs` (`createSampleCache`: the decoded buffer, its drawn peaks and its detected tempo each computed once per sound, `soundBehind` resolving a definition name to its pack sound, `forget(sound)` after an import; `createPreviewer`: the one-button preview and the `input.pvin` level, both pages on the one module) and mounts the shared `web/waveform.mjs` component (`createWaveform`, also mounted by the sample workshop page) to draw it, drag a break or a region edge, and snap to the beat grid (`web/sampler.mjs`: `detectTempo`, `barsGuess`, `snapTo`, `SNAPS`); **import** PUTs the file to `/samples/user/<song>/<name>.<ext>` (new route, `SAMPLE_FILE`), writes `pack.json` when a license is given, re-registers the user map, and `addPack` (`lib/resolve.mjs`) declares the pack in the song header. `samples/user/demo-pack/pack.json` defines `loop`, `loop-kick` and `loop-snare` on the generated `loop.wav`; `songs/chop.strudel` is the worked example; `samples.html` (local dev only, not in `PAGES`) is where a definition itself gets made. `test/sample.test.mjs` covers the layer, the check and the dump round trip.
- **Patches** (`lib/patches.json`: `pluck`, `reese`, `hollow`, `glass`, `breath`, `wide`, `sub`, vocabulary-like data rather than code): named bundles of voice controls (`PATCH_KEYS` in `lib/packs.mjs`: resonance, filter and pitch envelopes, FM, noise, unison/detune, vibrato) applied under the axes. `patch` is a material on `bass`/`melody`/`pad`, resolved by `resolvePatch` from a name in `PATCHES` or an inline object validated against `PATCH_KEYS`.
- **scripts/check.mjs** runs Strudel in Node: `evalScope` over core/mini/tonal with stubbed `setcps`/`samples`/`hush`, loads `lib/index.mjs`, `evaluate(code, transpiler)`, then `pattern.queryArc(0, 4)`. Bank-prefixed sounds resolve as `<bank>_<name>`. Exports `checkFile` and `ensureScope` for the other scripts. For `song()` files each section carries `energy` (onsets per cycle over its parts, scaled by level) and each layer `words` (`describeAxes`); the CLI prints the words after each layer's attrs and an `arc:` line of section energies with bar glyphs. The `sounds` block and each layer's `sounds` carry `seconds`/`rms`/`peak` from the pack meta files (`samples/packs/<pack>.meta.json`, `samples/user/<pack>/meta.json`, written by `scripts/samplemeta.mjs`, keyed by the map's file string; `soundMeta` takes the variant file or the median over a pitched instrument's files), `minNote` is the layer's lowest midi note, and `load` counts a hit with no `clip` for its file's length (superdough plays an unclipped sample to the end: strata's timpani kit stacked ~30 of its 11 s takes where hap lengths said 6). The lint reads those for two static rules: a part whose loudest sample times its level sits 36 dB under the section's loudest sampled part is "inaudible before any render", and a layer reaching under midi 20 is sub-audible. For `song()` files the result also carries `visual`, the score `lib/visual.mjs` `composeVisual` derives from `pattern.strudel` and the onset counts (mood, world, palette, cast, sections with energy and transitions; every aesthetic table is `lib/visual.json`, every function takes a policy), printed as a `visual:` line after `arc:` through `describeVisual`; each built layer keeps its structural `plan` (frozen plain data, `withPlan` in `lib/layers.mjs`) for it, and `classifyHap` reads a bare hap for patterns with no song behind them. `lib/random.mjs` holds the seeded `prng` the layers, `gen/` and the score share.
- **lib/dump.mjs** has no source to print (song() builds patterns at runtime), so `dump(code, { modules, Pattern, evaluate })` wraps every core function and Pattern method for the duration of one evaluation, records the call chain behind each pattern, prints it per section and layer, and then restores the originals. Every dump opens with `prebakeHeader` (`lib/packs.mjs`, built from `lib/packs.json`): the `samples()`/`aliasBank()` calls the page runs at boot, plus the deployed `samples/user/` map when the song declares packs, because strudel.cc prebakes a different set and a paste would otherwise warn "sound not loaded". `scripts/dump.mjs` drives it from Node (`dumpFile`), `index.html` from the page: the expanded pane re-expands the textarea 300 ms after each edit (and on play), so it reflects the textarea, not disk, and the Strudel export/open buttons use that same expansion. On GitHub Pages, save and new song fall back to localStorage under a `strudel:` prefix and the song list merges those drafts.
- **lib/resolve.mjs** parses the song with acorn and edits only numeric literals that are direct values of axis keys inside `section()` layer objects, plus the `key`/`progression` strings for harmony words. Signals and hand-written expressions are refused, never rewritten. `scripts/resolve.mjs` is its CLI; the Compose page imports it too (an import map in `index.html` points `acorn` at `node_modules/acorn/dist/acorn.mjs`, which `scripts/pages.mjs` ships) for the **Mix card**. The card shows one section (the playhead's, or the pinned one) as a layers × axes grid of sliders: `setAxis` rewrites or inserts one literal in the textarea; a layer built with spread shows the evaluated song's values and a drag appends an override after the spread; a signal cell draws `web/lane.mjs`'s `laneSvg(lanePoints(pattern, cycles), cycles)` in place of `expr`, sampling the evaluated attr pattern across the section. Every continuous axis carries a `▾` shape pick (`openPickList` over `constant`/`ramp up`/`ramp down`/`wobble`/`drift`/`pulse`/`swell`) that writes the chosen movement centred on the cell's current value through `setAxisText` (`lib/resolve.mjs`: like `setAxis` but takes source text as-is, so it can replace an existing signal too, not just a number). A ⚡ pick on each arrangement-strip block runs one of `VERBS` (`breakdown`, `lift`, `strip`, `halftime`) through `applyVerb` (`lib/resolve.mjs`: a whole-section resolver phrase, a material change and/or a part cut, also on the CLI as `--verb`), and a `dropout`/`sweep` bar count on each block writes the section key. Words go in as pills in the open **adjust via vocabulary** panel under materials (Verify's comparison lands inside it; the status line stays outside, since knobs and previews write it too): the box is a native `<datalist>` of the vocabulary tables plus the section's part names (`listTerms`, rebuilt by `mixRender`), and only a term becomes a pill (Enter/Tab/comma on the typed word or on a prefix only one term starts with; a pick from the list arrives as a `change` event), a part pill scopes the pills after it to that part, and each clause runs `planEdits` (which takes the evaluated attrs as a fifth argument so spread layers resolve; the CLI without them still refuses spread layers). Verify renders the section before and after the words with `renderSong`, measures both with `lib/analyze.mjs` (the analyzer's pure half; `scripts/analyze.mjs` keeps the wav I/O and CLI), shows the deltas per requested axis (`verifyRows` in `web/compose.mjs`) next to a player for each with a close button, reports progress on an `xstate` badge, and applies the edit. A **measure** button next to A/B does the same rendering step on the section as it stands, plus one render per part alone (`renderSong` one at a time: it shares the offline context), and turns each into `rms`/`peak` with `lib/analyze.mjs`; `levelRows` (`web/compose.mjs`) turns those into a dB reading per part relative to the mix (the mix row itself in dBFS) and a `warn` for no headroom or silence, written next to each level slider and, for the mix, on its own `mstate` badge beside the button. It writes nothing. The **arrangement strip** sits under the card's header: a block per section, flex-grown by span, one row per layer shaded by density × level, click to scrub, the playing one outlined, with a pin (loop it, Play starts there, the card stays on it, a plain click on another block moves the pin: the scheduler is handed the section's own pattern at its own cps via `scheduler.setPattern`, which loops by itself with nothing scheduled past its edges, and the page converts between song cycles and section bars with `toSong`/`toLocal`; unpinning hands the song pattern back at the equivalent cycle), rename (the ✎ op or a double-click on the name opens a box in the block; `renameSection` rewrites the name literal and refuses empty, quoted or taken names), move-earlier/later arrows (`moveSection` swaps the two call texts), duplicate (`duplicateSection`, next free numbered name) and remove (`removeSection` cuts the call with its line and separator). Two closed panes, **song** (above the strip, since it is not about one section) and **section** (above the knobs), are `spanPane`s: a CodeMirror 6 editor (`web/cm-editor.mjs` `createEditor`, loaded straight from node_modules through the import map in `index.html`, which `scripts/pages.mjs` ships package by package) over one span of the source. `show(node)` re-reads the span after every edit (`setText`), and an edit in the pane (typing, a control, an alt-drag) splices the source at that span through `commit`, so the knobs, expansion and player follow; while a pane or one of its controls has focus (`typing()`) `mixRender` re-finds its span by start position (a section's name may be mid-edit) and leaves the text alone, and undo blurs it first. The song pane shows the header object of `song(...)` (`locate` returns it as `song`) parsed as one expression (`languageFor('song')`, lezer's `SingleExpression` top) with `root: 'song'`, so its keys read as song's; the section pane shows the whole `section(...)` call. The editor has no history extension: ctrl+z reaches the page's stack. `web/cm-controls.mjs` is the inline-control extension, an experiment ahead of moving the main pane to CodeMirror: `web/hll-schema.mjs` says which literals have known semantics (`props` by object key inside a `song`/`section` object, its layer objects, or a `map` such as `drums.sounds`: numbers with bounds, enums, bools; `calls` by positional argument: section's cycles; `free` names the keys that stay hand-written, and a test checks every key the HLL accepts is in one or the other; `host.sounds`/`host.kits` are getters the page fills with what is loaded) and everything else stays plain code; `findControls` re-finds them from the lezer tree after each change (a state field, half-typed code included), each gets a dotted underline, the **controls** checkbox in the panel's summary (`#tweak`, kept in localStorage) puts a widget after each (`editFor` dispatches the replacement of exactly that literal, quantized to the spec), and alt-drag on a known number changes it in place (the codemirror-interact gesture, bounded by the spec; open numbers step every 8 px). Strudel expressions in a value are covered too: `signals` (`sine`, `saw`, ...) as a pick, `methods` (`.range`, `.slow`, `.fast`, `.segment`) and `calls` (`ramp`) by argument, where `'inherit'` means the bounds of the HLL number the expression is the value of. The widgets are in `web/cm-widgets.mjs`, one factory per kind chosen by `widgetFor`: slider (number with a max), spinner (number with only a min), check, tokens (the progression as a row of chord pick buttons plus +, brackets kept), pick (a `button.pick` like the materials panel's that opens the host's menu, with a ▶ when the value can be heard) and select (the native fallback without a host). The host hooks come in through `createEditor({ ui })`: the page's `editorUi(sectionAt)` gives `pick` (the shared `#pick` popover through `openPickList`, which the materials panel's `openPick` now also uses; its preview level slider hides when the menu has no play buttons), `audition`/`canAudition` (the materials audition path by control path in the section `sectionAt(control)` names, `auditionKit` for `kit`) and `icon` (the kit svg). The **Song source** pane is the same editor: `code = createEditor({ light: true, ... })` replaced the textarea, `code.text`/`code.setText` are what `$('code').value` was everywhere, its `onChange` is what typing was (commit, `sourceChanged`, `expandSoon`), a control's section is the call around it (`sectionAround`), and its header carries a third controls checkbox (`#tweak2`, after `#tweak0` on the song pane and `#tweak` on the section pane; `setTweak` keeps all three editors and the `strudel:tweak` setting together). Its controls take the page's light styles under `.pane`, the rack's dark ones under `.rack`. Tested in `test/cm.test.mjs` on `EditorState` alone, the chooser included. An **add part…** dropdown ends both the axes and the materials list (`#addaxes`, `#addmats`, one option per kind, filled by `mixRender`): a pick inserts `layer: {}` (`addLayer`) and the re-render puts the dropdown back on its placeholder; the × on a knob row removes one (`removeLayer`); a second part of a kind is `drums2`, which `song()` builds with the layer named by the key minus its trailing digits (`layerBase`). A closed **materials** details under the knobs shows one line per part: drum `template` (select over `TEMPLATES`, or the step grid editor `web/stepgrid.mjs` — voices × steps, click to cycle rest/hit/accent/ghost — once it is a written `{ voice: grid }` object) and per-voice `sounds`, the `sound` of the other parts, bass and melody `notes` (the written line; empty = the seeded line), melody `phrase` (shown as bars; 1 is dropped) and `follow`, pad `arp`. Under the bass and melody notes box a closed **roll** (opens when the notes box takes focus; its summary carries a play button, `data-pvnotes`, that auditions the part with the line as the box has it; `web/roll.mjs`: degrees × slots over the written line, or the seeded/default one until a click writes it; click sets a note, again rests it, inside a hold splits it, shift-click holds the note before through the slot; `parseLine` refuses any notation beyond degrees, `~` and `@n`, and the box stays text-only) writes `notes` the way the step grid writes `template`. Template, arp, sound and the drum voices are `button.pick` menu buttons that open the one shared `#pick` popover (filter box, rows from `TEMPLATES`, `ARP_ORDERS` or the `#snds` datalist of synth names plus every loaded sample); every row carries a ▶ that **auditions** without selecting, and the text boxes (notes, bars) show a ▶ while focused. Each row ends with a **level** slider (0..2, the part's gain multiplier; 1 is dropped from the source), the volume control the axes lack. The kit menu rows carry the same ▶ (a `span.pv`, since a button cannot nest one): `auditionKit` plays the same two bars (`KIT_GRIDS`: twelve voices, the house groove with rim and cowbell, then ride, crash, clap and a tom fill) through that kit at the shown section's tempo, so every kit is heard on the same material; voices the kit lacks (`hasSound`) are dropped and named in the status. All of these go through `preview(btn, build)` / `run` (build returns `{ pattern, cps, what }`); `audition()` is the material case. It pauses the song (so Play says Resume), resumes the AudioContext itself (it may be the page's first click, and superdough's `initAudio` does not actually resume), evaluates the source with `setMaterial` applied, and hands the scheduler only that section's layer pattern for two bars at the section's cps through the repl's `setCps`/`setPattern` (the `setcps` global only exists once a song has been evaluated); pressing the same ▶ again, or closing the menu, ends it early. A drum voice previews alone through `voiceSound` from `lib/layers.mjs` (the drums part's own rule: a name the kit has keeps the kit, `rim` → `RolandTR909_rim`; any other sample plays bare, because superdough looks up `<kit>_<name>` and nothing else once `.bank()` is set; `hasSound` in `lib/strudel.mjs` asks the page's sound map and is undefined in Node, which then assumes the kit), because the built part would drown it or, below the voice's density threshold, not contain it at all. A **preview level** slider sits at the bottom of the panel and again in the menu header (`input.pvin`, log scale x0.1..x50, `pvGain` kept in localStorage under `strudel:pvlvl`, never written to the song): every preview is multiplied by it, and a running one restarts on release. Values come from the source literal or the evaluated song (a spread); `matText` builds the literal (`sounds` is the whole voice map with one voice replaced) and a change goes through `setMaterial` (`locate` records material properties as `mats`, literal or `expr`; null text removes the key). Every source change (typing, knobs, pills, section ops, kit) goes through one undo stack in the page (`commit`), coalescing typing and knob drags within a second; ctrl+z / ctrl+shift+z and undo/redo buttons on both the source pane and the mix header (`.undo`/`.redo`). The expanded pane scrolls its changed line into view by setting its own scrollTop, never scrollIntoView, so a mixer click does not move the page. **What you hear vs what is written**: solo/mute (M and S on a knob row, sets of part names) and A/B (the summary button: the source before the last undo step, evaluated with `evalCode`, on the same clock; any commit turns it off) never touch the source. `audible(pat)` derives the scheduler's pattern from an evaluated song: the pinned section's parts alone, or the song rebuilt with `stepcat` the way `song()` arranges it, keeping only the parts that pass; `setLive()` hands it to the scheduler, and `play`/`applyPin` go through it. `globalThis.strudelBench.live()` returns the scheduler's current pattern for headless checks. The "all sections" checkbox on the phrase row makes words and knobs land in every section that has the part (`planEdits` with `'*'`, `setAxisScoped`). Keys: space plays/pauses outside text fields, ctrl+s saves, ctrl+enter updates; `beforeunload` asks when there are unsaved edits. Export renders the pinned section alone as `<song>.<section>.mp3`. **Seeing**: under each knob row an event strip (`evRow`) draws the part's onsets over the section's bars from the evaluated song, with bar lines from `--bars` and a playhead from `--ph` on `.knobs`, which `showPosition` sets while the shown section sounds. **Harmony row** above the knobs (`harmRender`): the section's key (the song's, marked, unless the section names one) and one pick per bar of the progression showing the chord name over its numeral, plus a + bar; picks go through `setSectionField` (key/progression on the section: replace, insert after role, or drop) with the `CHORDS`/`ROOTS` lists exported by `web/hll-schema.mjs`; the transport readout appends the chord under the bar (`chordAt`). **Seed per part**: `song()` gives every layer `seed` as material (`lctx`), the melody row in materials has a seed box (placeholder: the song's) and a next button. **Provenance**: `did` remembers every mixer edit in `pending` (a drag coalesces), and Save appends them to `songs/<name>.notes.json` as one dated request, "edits made in the mixer", with layer/axis/to parsed from knob messages so the notes card tags them (`saveNotes`; local server only). **Share link**: the export group's Link button copies `<page>#s=<base64url(deflate-raw("name\nsource"))>` (`shareEncode`/`shareDecode` in `web/compose.mjs`, native CompressionStream, tested in Node); `loadList` decodes `#s=`, lists the name if it is a legal song name, and puts the source in the editor unsaved, then sets the hash to the name so a reload does not re-import. **Transitions**: each strip block (except the last) ends with two picks, `riser` (bars of sweep at the end of this section, `fx.riser`) and `hit` (the next section's `fx.impact`, with a preview); `withFx` adds an fx part when the section has none, and the values shown come from the evaluated sections.
- **gen/** generators are plain scripts that print Strudel code to stdout with a seeded PRNG; each exports `generate(seed)` so tests can run output through `checkFile`. `gen/form.mjs` (`generate(seed, { mood, bars })`, `MOODS`) emits a `song()` skeleton: the `ARC` of six roles with base values per part, bars in fours from the length, `FEEL` per mood (mode, verse and climax progression words from `lib/harmony.json`, tempo), and the mood's `lib/overlays.json` vector added to every part where it pushes hard or where the part already sets that axis; `test/gen.test.mjs` generates every mood and checks it clean with a climax.
- **scripts/lint.mjs** exports `lint(checkResult)` → `[{ level, section?, text }]` over the check's sections (energy, layers with attrs): the skill's rules as findings (no climax, climax not the peak, identical consecutive sections, raw saws sharing a section by effective sound with `lib/layers.mjs` defaults, melody/bass without notes, axes outside 0..1 as errors, level outside 0..2). ## Node gotcha

`@kabelsalat/web` (pulled in by `@strudel/core`) ships no `exports` map, so Node resolves its CJS build and named imports break. Any Node script importing `@strudel/*` must `import './esm-fix.mjs'` (a `registerHooks` resolve hook) first and then use dynamic `import()` for the strudel packages, as `scripts/check.mjs` does. `lib/` never imports `@strudel/*`: it reaches Strudel through `lib/strudel.mjs` (`S`), which is `window.strudel` in the page and `globalThis` after `evalScope` in Node.

## Axes

A song can be written declaratively: `song({ cps, key, seed, kit }, [section(name, cycles, { role, key, progression, drums: {...}, bass: {...}, melody: {...}, pad: {...}, fx: {...}, sample: {...}, perc: {...}, raw: {...} })])`. Each layer takes axis values in 0..1, where **0.5 is the baseline no-op** (enforced by test) and a continuous axis may also take a Strudel signal or `ramp(a, b)`; structural axes take numbers only. `key` and `progression` are per-section harmony (rule 4: harmony is material, not an axis); material keys (`sound`, `level`, `fill`, `arp`, `follow`, `kit`, `meter`, `bpm`, ...) live next to axes in the same layer/section objects. `sound` (and drum voices in `sounds`) may also be a list, a weights object, or a double-quoted mini pattern, for a deterministic pick per hit or per bar instead of one name. `test/golden.test.mjs` pins the full event stream of the fixture songs in `test/fixtures/`; regenerate it (`UPDATE_GOLDEN=1 node --test test/golden.test.mjs`) only on purpose, when lib changed how songs build, and check that only the fixtures you expected moved.

- `lib/axes.mjs` — the 12-axis registry (`AXES`), `PHASES` (structural → timing → pitch → articulation → spectral → spatial → level), and the `ctl`/`piece` mapping helpers.
- `lib/layers.mjs` — the eight layers (drums, bass, melody, pad, fx, sample, perc, raw) and their per-axis cells.
- `lib/grid.mjs` (step grids and placement, parametric on meter; the one written-rhythm grammar is `x`/`X`/`o`/`.`/`|` or `p/s[+r]` euclidean, parsed by `parseGrid` and shared by a drum voice's `template`, `bass.rhythm` and `perc.rhythm`), `lib/song.mjs` (`song`/`section`/`registerLayer`; parts play on superdough orbits, `.orbit(n)`, where reverb and delay live: parts whose reverb would be identical share one (`orbitKey`: every part under a `room` that sets `size`; bass and melody at any space, since their cells never set a size; else the same layer kind at the same `space` number; a ducked part, a raw part or a space signal on a size-setting layer gets a private one; keyed by layer kind, so a new cell that sets a size or a delay time must be added there), numbered in order of first appearance, so a 13-part section is not 13 convolvers; a layer's `duck`/`duckDepth` material points that part's own hits at another named part's orbit as a sidechain, superdough's `duckorbit`/`duckdepth`; section keys `dropout: n` and `sweep: n` mask every part but fx for the last `n` bars, silence or a closing low-pass), `lib/harmony.mjs` (roman-numeral progressions over a section key, `chordName`, harmony words), `lib/vocab.mjs` (phrase → axis deltas; `MODIFIERS` scale them).
- `lib/index.mjs` loads all of it into the current scope and defines `song`, `section`, `strudelLib` and one global per layer (`drums({ density: .8 })` returns just that layer's pattern) on `globalThis`.
- Vocabulary is data, not code: `lib/descriptors.json` (control words), `lib/overlays.json` (emotions/genres), `lib/harmony.json` (progression and mode words), `lib/verbs.json` (the arrangement verbs `applyVerb` runs: a phrase, a material change, a part cut), `lib/motion.json` (motion words → the `wobble`/`drift`/`pulse`/`swell`/`rise`/`fall` movements in `lib/axes.mjs`). Node reads them eagerly, the page fetches them via `/lib/`. Add words there, then `npm run vocab`.

README.md carries the rules, the axis table, the phase order and the harmony contract, because `docs/` and `.claude/` (except the strudel skill) are gitignored here.
